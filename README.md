# Cancer Var

Учебный проект классификации опухолей на встроенном наборе `load_breast_cancer` из scikit-learn: сравнение моделей, калибровка вероятностей, HTTP API, отчёты мониторинга и CI.

Набор содержит 569 наблюдений и 30 числовых признаков, вычисленных по изображениям образцов. Самих изображений в нём нет. Метки: `0` — malignant, `1` — benign. Результат API — оценка класса моделью, а не клинический риск пациента. Проект не предназначен для диагностики или выбора лечения.

## Запуск в Jupyter Notebook

Весь исполняемый код находится в `cancer_var.ipynb`. Python-модули и отдельные файлы тестов заменены ячейками ноутбука. README, зависимости и конфигурация CI остаются обычными служебными файлами.

Требуется Python 3.10 или новее. Выполните из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name python3 --display-name "Python 3 (ipykernel)"
jupyter lab cancer_var.ipynb
```

В Windows используйте `.venv\Scripts\activate`. Выберите ядро из созданного окружения, затем `Restart Kernel and Run All Cells`.

Ячейки идут по порядку: импорты и настройки → функции оценки → обучение и сравнение → сохранение → мониторинг → API → проверки → необязательный HTTP-сервер. Ноутбук хранится без результатов выполнения; метрики появляются после запуска. Рабочая директория ядра должна быть корнем проекта или вложенной папкой.

## Обучение

Стратифицированное разбиение с seed 42 выделяет 20% данных для итоговой проверки. Остальные 80% используются для сравнения четырёх вариантов:

- логистическая регрессия с масштабированием признаков;
- случайный лес;
- логистическая регрессия с сигмоидальной калибровкой;
- случайный лес с сигмоидальной калибровкой.

Каждый вариант оценивается на пяти стратифицированных фолдах. Калибратор использует три внутренних фолда; масштабирование находится внутри конвейера и обучается заново в каждом фолде. Вариант выбирается по минимальному среднему log loss. Калибровка не обязана улучшать результат, поэтому в сравнении остаются и исходные модели.

После выбора модель обучается на обучающей части и один раз оценивается на отложенной. Тестовая выборка не участвует в выборе. Порог классификации фиксирован: вероятность malignant не меньше 0.5.

Результаты сохраняются в `artifacts/`:

- `breast_cancer_pipeline.joblib`: модель, признаки, статистики обучающей выборки и метаданные;
- `metrics.json`: accuracy, precision, recall, F1, ROC AUC, Brier score и log loss;
- `training_report.json`: результаты сравнения, выбранный вариант, индексы разбиения, калибровочная кривая, версия scikit-learn и фактическое время обучения.

Меньшие log loss и Brier score лучше. Для остальных перечисленных метрик лучше большие значения. Небольшая отложенная выборка даёт лишь предварительную оценку; калибровочная кривая из пяти интервалов тоже может быть нестабильной.

## API

Чтобы запустить HTTP-сервер, после выполнения предыдущих ячеек задайте `RUN_API = True` в ячейке настроек и выполните последнюю ячейку. Она работает до прерывания ядра; по умолчанию запуск сервера выключен, чтобы Run All и CI завершались. Встроенные проверки API используют TestClient без сетевого порта.

Документация с формой отправки запросов доступна по адресу `http://127.0.0.1:8000/docs`.

| Endpoint | Назначение |
| --- | --- |
| `GET /health` | Наличие файла модели; 503 при его отсутствии |
| `GET /features` | Имена и порядок 30 признаков |
| `POST /predict` | Предсказание для JSON `{"features": [...]}` |

`features` должен содержать ровно 30 конечных чисел в порядке из `/features`. Неверный размер или тип возвращает 422. Ответ содержит `model_probability_malignant`, `model_label` и ограничение применения. Отрицательные значения и диапазоны, не встречавшиеся при обучении, отдельно не проверяются; API не подтверждает медицинскую корректность введённых измерений.

Артефакт кэшируется в памяти после первой загрузки. После переобучения перезапустите сервер. Используйте только доверенные joblib-файлы: их загрузка может выполнять код.

## Мониторинг

Подготовьте CSV с заголовками, совпадающими с именами признаков из `/features`. Порядок столбцов не важен. Необязательный столбец `target` содержит истинные метки 0 или 1, полученные независимо от модели.

После выполнения ячейки с функцией `monitor_csv` добавьте новую ячейку:

```python
monitor_csv("observations.csv", "reports/batch-001.json", shift_threshold=0.5)
```

Параметр `model_path` позволяет выбрать артефакт. Пример мониторинга в ноутбуке использует отложенные данные исходного набора и проверяет работу отчёта; он не имитирует реальные новые наблюдения.

Мониторинг работает пакетно при вызове функции, а не непрерывно. Для каждого признака он считает абсолютное смещение среднего относительно обучающих данных, делённое на обучающее стандартное отклонение. Порог 0.5 — настраиваемая эвристика, а не статистический тест. Отчёт перечисляет признаки, превысившие порог. Проверка среднего не обнаруживает все изменения распределения.

Без `target` качество остаётся неизвестным: отчёт содержит `quality: null`. При наличии меток считаются метрики и их разность с отложенной оценкой. Рост log loss или Brier score указывает на ухудшение; для ROC AUC и полноты ухудшением является снижение. При единственном классе ROC AUC равен `null`. Разность метрик не доказывает статистически значимого ухудшения. Сохраняйте отдельные отчёты по периодам для наблюдения динамики.

## Проверки и CI

Проверки находятся в ячейках после определения API. Они проверяют соответствие вероятностей, некорректные запросы, отсутствие модели, порядок признаков, раздельность выборок, выбор модели, сдвиги признаков, единственный класс, неверные метки и обработку CSV. При ошибке выполнение прерывается исключением AssertionError.

```bash
ruff check cancer_var.ipynb
jupyter nbconvert --to notebook --execute cancer_var.ipynb --output executed.ipynb --output-dir artifacts --ExecutePreprocessor.timeout=600
```

GitHub Actions проверяет структуру ноутбука, запускает линтер и выполняет все ячейки на Python 3.10 и 3.12. Выполненный ноутбук и JSON-отчёты сохраняются как артефакты CI. Модель повторно обучается один раз за запуск ноутбука. Диапазоны зависимостей заданы в `requirements.txt`; версии библиотек могут влиять на результаты.

## Ограничения

Это небольшой исторический учебный набор, который не представляет все группы пациентов и условия получения данных. Даже калиброванные на нём вероятности не валидированы для клинической практики. Для медицинского применения необходимы независимые данные, клиническая валидация и экспертный надзор. Не публикуйте персональные медицинские данные в этом репозитории.
